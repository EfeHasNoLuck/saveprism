## User rules (2026-10-22)
- Calm, not a busy document: no icon in front of every section title, no always-visible helper lines (put them in an (i) tooltip next to the
  title), no "CURRENCY" overline, no currency symbol, no green dots, no "Ready to edit"/"Safe to edit" labels.
- Side-by-side layout from 1024 px: row 1 Gold (narrow) + Characters (wide: list left, Level/HP/MP/EXP then "Stat bonuses" 4-column
  grid right). Row 2 Items · Weapons · Armors side by side. Row 3 Variables (wide) + Switches. One surface per row, thin dividers.
  Title 16 px semibold, labels 13 px, values 14 px tabular numbers.
- Type hints are wanted: show `field.hint` + " · was {original}" under a field **only when it is focused or changed** (Gold always).
  Out of range → hint in the error color, field marked invalid, `onInvalidChanged(true)`.
- Switches: the shadcn Switch at its normal size (h-5 w-9) in a `shrink-0` wrapper, right-aligned. Never stretched.

## Yapılacaklar
1. Load `gameView()` on mount. `kind: "rpgmaker"` → sections above; `kind: "values"` → one "Values" card: search box, table
   Name · type tag (`field.typeLabel`) · editor; group rows (field null) expand with `getChildren(row.path)` + `fieldInfo(child.path)`.
2. **Field editor** (one component for all): int → number input with − / + steppers (step 1, clamp to min/max); float → number input;
   bool → Switch; string → text input. Commit with `editValue(path, text)` on blur/Enter; show backend errors inline (message + hint).
   Changed (value ≠ original) → soft brand highlight + small undo arrow that calls `editValue(path, original)`.
3. Lists (Items, Weapons, Armors, Variables, Switches): small search ("Search name, #id or value"), rows `name ?? "Item #<id>"` (Weapon/
   Armor/Variable/Switch likewise), grey `#<id>`, editor right; Variables/Switches paged 50 per page with "1 / 3" pager.
4. Characters: list of actors (initial avatar, name, "Lv 12"); selecting one shows its fields. If `namesFolder` is set, an (i) tooltip on the
   section title says "Names from <folder>".
5. After every successful edit call `pendingChanges()` and report the count via `onChangesChanged`.
6. `readOnly` → all inputs disabled.
