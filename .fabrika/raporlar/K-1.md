## Behaviour notes
- Encrypted ES3: detect cannot pass a password, so on detect failure + `crypto.es3-aes` sniff the app tries `[aes, es3]` then `[aes, gzip, es3]` itself. No password -> SP-ES3-005; wrong -> SP-ES3-004 (codec codes reused).
- Guard for encrypted files is computed in the app (re-encode with password, compare bytes / tree_eq), because core `check_round_trip` re-encodes layers with the returned params, which lack the password, and would report `failed`. Possible core improvement: let the guard take a password hint.
- `save`: core `safe_write` (backup in `default_backup_root`, temp, atomic replace); verify closure re-decodes and compares every edited value; failure -> core restores backup and returns SP-IO-004. Success switches the session to the written path and clears pending. Params: `overwrite` optional (default false).
- Search matches the full path text literally (so `/items` also hits all descendants), plus scalar value text.
