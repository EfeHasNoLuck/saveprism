## Files (all under crates/saveprism-codecs/src/layers/)
- mod.rs: error codes SP-LAY-001..006 (`LAY_BASE64_INVALID`, `LAY_GZIP_INVALID`, `LAY_ZLIB_INVALID`, `LAY_LZSTRING_INVALID`, `LAY_INVALID_UTF16`, `LAY_ENCODE_FAILED`), `register`, param helpers, register test.
- deflate.rs: shared bounded `inflate` (DeflateDecoder + `read_bounded`, `total_in`), `deflate`, `find_level` (order 6,9,1,2,3,4,5,7,8,0; skipped above 64 MiB), `level_param`.
- gzip.rs, zlib.rs (own Adler-32), base64.rs (hand-written, no `base64` crate), lzstring.rs (bounded port, MIT attribution in header).

## Parameters
- encoding.base64: alphabet ("standard"|"url"), pad, wrap, newline ("lf"|"crlf"), trailing_newline, irregular (set on decode; encode ignores it and writes canonical). Non-canonical trailing bits also set irregular. All optional on encode (defaults standard, pad true, wrap 0, lf, false).
- compression.gzip: mtime, xfl, os, ftext, fhcrc, fname?, fcomment?, fextra? (bytes), level, exact, trailing? (bytes, <= 64 KiB). Defaults on encode: 0, 0, 255, false, false, level 6.
- compression.zlib: cmf, flg, level, exact, trailing?. FDICT -> SP-LAY-003 "preset dictionary not supported". Fallback level from FLEVEL (0->1, 1->5, 3->9, else 6).
- compression.lz-string: variant ("base64"|"uri"). On decode the variant may come from the recipe hint `variant`; otherwise guessed ('-' or '$' -> uri; '/' or '=' -> base64; else length%4 != 0 -> uri; else base64).

## Acceptance mapping
1. Round trips: per-file tests (base64 standard/url/unpadded/76 CRLF/trailing newline/all lengths; gzip fname+mtime+os+fextra+fcomment+fhcrc, levels 1/6/9, hand-made two-stored-block stream gives exact=false; zlib 78 01/9C/DA).
2. lz-string: proptest base64 and uri round trip; "a"*10000 hits CORE_LIMIT_DECODED with max_decoded_bytes=1000 (units are counted before each write, dictionary entries are parent-linked so memory stays bounded).

4. Damaged input tests (cut header, bad CRC/ISIZE/Adler, cut stream, invalid base64, invalid lz-string, unpaired surrogate -> SP-LAY-005).
5. mod.rs test: four ids registered.

## Uncertain points
- lz-str 0.2 function names/signatures assumed: `lz_str::compress_to_base64(&str) -> String`, `lz_str::compress_to_encoded_uri_component(&str) -> String`. If they take a different input type, only `encode` and tests in lzstring.rs change.
- flate2: `read::DeflateDecoder::total_in()`, `write::DeflateEncoder`, `Crc::{new,update,sum}` assumed as in flate2 1.x.
- (Fixed in correction round) gzip/zlib level tests no longer assert `level_found == level`; they assert `exact == true` and byte-identical re-encode only.
- `manual_is_multiple_of`-style clippy lints avoided with `& 3` and `> 0`; other clippy nits may appear.
- The `base64` crate dependency is unused (own implementation for exact layout control); harmless unless `unused_crate_dependencies` is on.

## Correction round
- lzstring.rs: `URI_ALPHABET` had 65 bytes under a `&[u8; 64]` type (compile error). It is now the 64 data symbols (`A-Za-z0-9+-`); `$` is the reference key string's 65th (padding) slot, never data. `alphabet()` keeps `&[u8; 64]`; `guess` and `in_any_alphabet` still treat `$` as a URI hint, so sniff test `abc-$+` still passes, and decode of a `$` byte gives SP-LAY-004 (not in alphabet).
- gzip.rs `levels_are_found_and_round_trip`, zlib.rs `headers_78_01_9c_da_round_trip`: removed the level equality assert (levels producing equal bytes are ambiguous); `exact` and encode byte equality kept.

## Düzeltme turu 3
1. lzstring.rs variant ambiguity: `Variant::guess` now returns `(variant, ambiguous)`; ambiguous = no `-$/=` and length % 4 == 0. A recipe hint `variant` always wins. If ambiguous, decode recompresses the result with base64 then uri and records the variant that reproduces the input byte for byte (base64 if neither). Test `ambiguous_uri_text_comes_back_unchanged` (also checks the hint path). Note: such texts usually compress identically in both variants, so the test asserts byte-exact re-encode, not a specific variant.
2. gzip.rs: bytes after the trailer starting with `1F 8B` -> SP-LAY-002 "multi-member gzip is not supported yet"; other bytes stay in `trailing`. Test `second_member_is_rejected_but_padding_is_kept`.
3. lzstring.rs: new `utf16_to_utf8_bounded` computes the UTF-8 length with `char::decode_utf16` + `len_utf8` (unpaired surrogate -> SP-LAY-005), checks it with `ctx.check_output`, then allocates with capacity. Test `utf8_size_is_checked_before_allocation` (100 x U+65E5 = 300 bytes: budget 300 passes, 299 -> CORE_LIMIT_DECODED).
- Verify: `cargo fmt --all` then `bash .claude/araclar/kontrol.sh rust`. Not compiled. `str::contains([char; N])` pattern in the new test needs Rust >= 1.58 (fine).
