## Decisions
- MV recipe in the golden files is `compression.lz-string > format.json` (not `encoding.lz-string`); unchanged, no new MV layer needed.
- JsonEx hint: `SaveDoc` has no public way to set `type_hint` after building, so a thin codec `format.rpgmaker-json` calls `JsonCodec.decode`, then copies the tree (only nodes reachable from the root, in id order, children first) and sets `JsonEx:meta` on the value node of every `@...` key (kept `JSON:float` nodes untouched). Encode delegates to `JsonCodec`.
- That codec's `sniff` is always NONE, so detection (and the MV golden expectations) stay `... > format.json`. A caller that sees `.rpgsave`/`.rmmzsave` swaps the last recipe step. If the CEO wants it auto-picked, raise its sniff above json's for those extensions and re-bless the MV expectations (not in my ownership).
- MZ: ASCII-only deflate output would make the binary-string layer an identity; the detector may then skip it (same bytes, dedupe). Harmless for round-trip.
